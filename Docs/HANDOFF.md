## 下一位开发者的推进顺序

1. **先完成 iOS 构建**：按 DEVELOPMENT.md 配置 Xcode、SDK、本地签名；运行核心检查、Package 测试、无签名模拟器构建。修复完整 SDK 才能发现的错误，记录 Xcode/SDK 版本与真实输出。
2. **查看两个页面**：检查权限引导、深浅色、照片网格、底部 Tab、最大字号、iPad 宽屏。当前通过 compact 环境保持底部 Tab，同时恢复子页面尺寸环境；新 SDK 上需确认是否符合系统行为。
3. **打通 GR4 单张传输**：按阶段定位发现、配对、凭据读取、开启热点、加入网络、身份、列表、下载、保存。失败时记录去敏后的 UUID/属性、错误码、型号/固件；不要盲目试写未知特征。
4. **核对原片**：PhotoKit 导出未修改原片，对照相机源 JPG 的 SHA-256；通过后才能说真实 EXIF/原片保留已验证。
5. **故障与压力测试**：按 DEVICE_TESTING.md 测 10/100 张、断线、取消、后台、进程退出、权限与磁盘空间，并记录平均有效吞吐。
6. **扩大兼容范围**：GR III、IIIx 和各 HDF 型号逐一验证；再处理 iPad / Duo 的运行布局。未测试型号保持待验证。

## 开发时必须保留的约束

- 优先原生 Apple SDK、系统交互与无障碍；现阶段无第三方运行时依赖。
- 原片不重编码；不能为了缩略图或提速把缩小版本保存到图库。
- 不在默认行为中删除相机照片，不改拍摄设置。
- 相机协议来源和真机支持范围分开记录。已发现 UUID 不等于该固件完整兼容。
- 保留正确的相机身份校验、原子日志、有限重试和取消行为。更改持久化 schema 时设计迁移，不能直接丢弃用户待导入照片。
- 测速后再调整并发；记录内存、吞吐和错误率，不能只看 UI 瞬时速度。
- 新 Mac 的签名放在忽略的 `Config/Signing.local.xcconfig`；工程设置持久修改同步生成器。
