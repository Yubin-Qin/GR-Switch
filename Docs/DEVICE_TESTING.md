# 真机联调与验收

## 当前设备与状态

目标设备：用户的 iPhone 14 Pro Max（用户提供系统版本 iOS 26.6.2）和 RICOH GR IV。截至 2026-10-07，本机 Xcode 正在安装，尚未建立真机开发会话。以下结果全部为 **待执行**；模拟服务测试不能代替相机实测。

## 1. 开发环境

- 从 Apple 安装完整 Xcode，启动并安装 iOS platform。使用支持目标 iOS 版本的 Xcode。
- 按 [开发环境与换机指南](DEVELOPMENT.md) 配置本机签名；Xcode Settings → Accounts 登录 Apple 账号，在 Signing & Capabilities 核对 Team。确认 provisioning profile 支持 Hotspot Configuration；如账号无法配置该 capability，需先解决开发者签名权限，不能仅去掉 entitlement 后宣称热点加入可用。
- 用数据线连接 iPhone，信任此电脑，开启开发者模式。先运行 App，确认系统没有缺少 capability 或 privacy description 崩溃。
- 不需要把 Apple ID 密码、相机 Wi‑Fi 密码或完整序列号发送到聊天。

## 2. 第一轮 GR IV 连接

1. 相机充足电量，准备少量包含 EXIF 的 JPG，分别放在 SD 卡/内置存储（如有）。记下固件版本。
2. 暂时退出 GR WORLD / Image Sync。在 GR IV 无线通信中开启 Action Mode，进入 Pairing → Execute Pairing。
3. App 设置 → 添加相机 → 搜索蓝牙相机。选择相机，并核对相机/系统配对提示。
4. 允许蓝牙、本地网络；同意加入相机 Wi‑Fi。没有互联网提示是相机热点正常状态。
5. 记录每阶段是否成功：发现、系统配对、SSID 读取、开启 Wi‑Fi、加入热点、`/v1/props` 身份验证、照片列表。
6. 蓝牙无法开启 Wi‑Fi 时，在相机中手动开启；若可查看 SSID/密码，使用手动连接。GR IV 不显示密码时，需要先解决 BLE 凭据读取，不能把该回退当作保证可用的替代流程。
7. 首先测试 1 张照片，再 10 张、100 张。分别选择系统图库、新建相簿、已有相簿。

## 3. 原片与 EXIF

- 保存后从 Apple Photos 导出**未修改的原片**；不要使用可能转码的分享/优化导出。
- 与相机 SD 卡中的源 JPG 用 `shasum -a 256` 比较。哈希一致是本轮原片/EXIF 保留的验收依据。
- 人工检查拍摄时间、方向、快门、光圈、ISO、焦距、镜头、GPS（有则检查）、MakerNote、ICC profile。
- 在完整照片权限与有限照片权限两种情况下验证保存和相簿可见性。拒绝权限后，队列不能丢失；恢复权限后能继续。
- 删除/撤销目标相簿访问后，App 应明确报错并保留暂存照片；移出该任务再以有效目标重新传输。

## 5. 故障注入

- 下载中关闭相机 Wi‑Fi、关闭相机、走出范围：有限重试后停止队列；已有成功照片不受影响。
- 下载中按暂停：停止当前网络任务，队列保留；继续时仅重做未完成照片。
- 下载完成/PhotoKit 提交前后强制退出 App：重启后核对 asset identifier，不能仅凭文件名假定已保存。
- 改连另一台 GR：身份不匹配时拒绝继续原队列。
- 进入后台/锁屏直至系统收回时间：暂停后回前台继续，不出现永久“正在传输”。
- 接近磁盘满、相册权限撤销、相机移除源照片：显示可理解的错误，保留可恢复状态。
- 在“传输记录”向左滑动移除未完成任务，不会删除相机照片或已保存资产。
